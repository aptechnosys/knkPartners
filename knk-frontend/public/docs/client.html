KNK Partners Client Integration API

This API allows authorized clients to submit cases, check case status, retrieve vendor cases and securely download verification proof documents.

Base URL

https://knkpartner.com/api/v1

Client → KNK Case Submission

Clients can submit verification cases using the following endpoint: 

POST /api-inbox/client
Replace the example client callback URL with the actual callback URL provided by your organization.

Authentication

All client API endpoints require an API key.

The API key must be sent using the x-api-key request header. 

x-api-key: YOUR_API_KEY
Content-Type: application/json
Keep your API key private. Do not expose it in frontend JavaScript, public repositories or client-side applications.

POST /api-inbox/client

Submit a new verification case to KNK Partners.

Request

POST https://knkpartner.com/api/v1/api-inbox/client

x-api-key: YOUR_API_KEY
Content-Type: application/json

Request Body

{
  "applicationId": "REF-2026-000888",
  "candidateName": "Faiyaz Khan",
  "fatherName": "Azad Khan",
  "dob": "16 Feb 1995",
  "city": "Mumbai",
  "state": "Maharashtra",
  "vendor": "APtechnosys Agency",
  "tat": 15,
  "remark": "Urgent verification"
}

  "vendor": "APtechnosys Agency",

GET /client/proof/{applicationId}

Securely download the proof document associated with a completed verification case.

Request

GET https://knkpartner.com/api/v1/client/proof/REF-2026-000888

x-api-key: YOUR_API_KEY
The proof document is protected by API-key authentication. The document is not publicly accessible.

Important

The API returns the proof document as a downloadable file. The client must send the API key in the x-api-key header.

Example cURL

curl -X GET \
  "https://knkpartner.com/api/v1/client/proof/REF-2026-000888" \
  -H "x-api-key: YOUR_API_KEY" \
  -o proof.pdf

Status Values

Status Description
NEW Case received and waiting for processing.
IN_PROGRESS Verification is currently in progress.
COMPLETED Verification has been completed.

Error Codes

Code Description
200 Request successful.
400 Bad request or invalid request data.
401 API key missing.
403 Invalid or disabled API key/client.
404 Case or proof document not found.
429 Too many requests.
500 Internal server error.

Webhook Notifications

KNK Partners can notify the client automatically when a verification proof has been updated.

The client must provide a callback URL during the client integration setup.

Event

PROOF_UPDATED

When is the webhook triggered?

The webhook is triggered when a verification case has been processed and its proof document is available.

Webhook Request

KNK Partners sends a POST request to the client's configured callback URL. 

POST YOUR_CALLBACK_URL

Content-Type: application/json

Example Payload

{
  "event": "PROOF_UPDATED",
  "applicationId": "REF-26-0002323",
  "candidateName": "Ayaz Khan",
  "vendor": "Ayaz_khan",
  "proofDocument": "https://knkpartner.com/api/v1/client/proof/REF-26-0002323",
  "verificationResult": "GREEN",
  "verificationDate": "2026-08-16T11:56:01.865Z",
  "status": "COMPLETED",
  "updatedAt": "2026-08-20T10:15:10.255Z"
}

Payload Fields

Field Type Description
event String Webhook event type. Currently PROOF_UPDATED.
applicationId String Unique application/reference number.
candidateName String Name of the candidate.
vendor String Vendor associated with the case.
proofDocument String Secure endpoint used to download the proof document.
verificationResult String Verification result such as GREEN, RED or ORANGE.
verificationDate Date Date and time when verification was performed.
status String Current case status.
updatedAt Date Last update timestamp of the case.

Downloading the Proof

The proofDocument value is a secure API endpoint. The client must send its API key when requesting the document. 

GET https://knkpartner.com/api/v1/client/proof/REF-26-0002323

x-api-key: YOUR_API_KEY

Example Webhook Handler

app.post("/webhook/knk", (req, res) => {

  const data = req.body;

  console.log("KNK Webhook:", data);

  if (data.event === "PROOF_UPDATED") {

    console.log(
      "Proof updated for:",
      data.applicationId
    );

    console.log(
      "Proof URL:",
      data.proofDocument
    );

  }

  res.status(200).json({
    success: true
  });

});
The client should return HTTP 200 after successfully receiving the webhook.
The proofDocument URL should not be treated as a public file URL. The client must use its API key when downloading the document.
