Quick Start

Get your first API call working in under 5 minutes.

  1. 01

    Obtain your credentials

    Contact your KNK Partners account manager to receive JWT credentials (for admin/agent login) or an API key (for vendor system integrations). Never expose credentials in client-side code.

  2. 02

    Authenticate

    Call POST /auth/login to receive a JWT token (internal users), or use your pre-issued API key in the x-api-key header (vendor integrations).

  3. 03

    Create your first case

    Submit a POST /cases request with the candidate's details. You'll receive a case object with status NEW.

  4. 04

    Track status in real time

    Poll GET /cases/:id or configure a callback_url webhook to receive automatic POST notifications on every status change.

Authentication

KNK Partners API supports two authentication schemes depending on your integration type.

JWT Authentication

Used by internal platform users (admins and agents). Authenticate via the login endpoint to receive a short-lived JWT token. Pass it as a Bearer token in the Authorization header on every subsequent request.

⚠️ JWT tokens expire after 24 hours. Re-authenticate when you receive a 401 Unauthorized response.
bash
# Step 1: Login to get JWT token
curl -X POST https://api.example.com/api/v1/auth/login \
  -H "Content-Type: application/json" \
  -d '{"email": "admin@example.com", "password": "YourPasswordHere"}'

# Step 2: Use token in all requests
curl https://api.example.com/api/v1/cases \
  -H "Authorization: Bearer YOUR_JWT_TOKEN..."

API Key Authentication

Used by external vendor systems integrating via Client Integration APIs. Your API key is scoped to your vendor account — you only access cases belonging to your organization. Pass it in the x-api-key request header.

bash
curl https://api.example.com/api/v1/client/status/REF-2026-001234 \
  -H "x-api-key: YOUR_API_KEY_HERE"
ℹ️ If your API key is compromised, an admin can regenerate it immediately via the Vendor Management API. The old key is invalidated instantly.

POST 🔐 JWT

Create Case

POST https://api.example.com/api/v1 /cases

Creates a new background verification case. Each case represents a candidate whose background needs to be verified. The case is automatically linked to the authenticated user as creator and defaults to NEW status. A callback_url can be provided to receive real-time webhook notifications on every status transition.

ℹ️ comp_ref_no must follow the pattern REF-{alphanumeric} (e.g. REF-2026-001234) and must be unique across the platform. Duplicate values return a 409 Conflict.

Update Case Status

PUThttps://api.example.com/api/v1/cases/:id/status

Updates the check_status of a case. Every status transition fires a POST webhook to the vendor's callback URL and creates an immutable audit log entry.

ℹ️ Webhooks are fire-and-forget — their failure does not block the API response. Check the API Logs section for webhook delivery status.
Request Body
FieldTypeRequiredDescription
check_statusstring (enum)requiredNew status. Valid values: NEW | IN_PROGRESS | Q_CHECK | DONE | INSUFFICIENT | ON_HOLD | STOPPED | REJECTED

  -H "Authorization: Bearer YOUR_JWT_TOKEN" \
  -H "Content-Type: application/json" \
  -d '{"check_status": "IN_PROGRESS"}'

PATCH🔐 JWT

Upload Proof Document

PATCHhttps://api.example.com/api/v1/cases/:id/upload-proof

Uploads a proof document (PDF, JPG, PNG) for a verification case. The file is stored and the URL is linked to the case. Maximum file size: 10MB. Use multipart/form-data encoding.

  -F "proof=@/path/to/document.pdf"

When a case's status changes, KNK Partners sends an HTTP POST to your configured callback_url. The webhook fires on every status transition including INSUFFICIENT queries and verification results.

  // Log the event
  console.log(`[KNK Webhook] ${applicationId} → ${status}`);

  // Update your local database
  await updateCandidateRecord(applicationId, { status, remark, updatedAt });

  // Respond with 200 within 10 seconds to acknowledge
  res.status(200).json({ received: true });
});

Webhook Best Practices
  • ✓Respond with HTTP 2xx within 10 seconds. Slow responses are retried up to 3 times with exponential backoff.
  • ✓Implement idempotency — the same event may be delivered more than once. Use applicationId as the idempotency key.
  • ✓Queue processing asynchronously — don't block the HTTP response on database writes.
  • ✓Use HTTPS endpoints only. Plain HTTP webhook URLs are rejected.
  • ✓Verify payloads by cross-referencing the applicationId against your local records.

const axios = require('axios');

class KNKAdmin {
  constructor() {
    this.baseUrl = 'https://api.example.com/api/v1';
    this.token = null;
  }

  async login(email, password) {
    const { data } = await axios.post(`${this.baseUrl}/auth/login`, { email, password });
    this.token = data.token;
    return data.user;
  }

  get headers() {
    return { Authorization: `Bearer ${this.token}` };
  }

  async createCase(payload) {
    const { data } = await axios.post(`${this.baseUrl}/cases`, payload, { headers: this.headers });
    return data.data;
  }

  async updateStatus(caseId, status) {
    const { data } = await axios.put(
      `${this.baseUrl}/cases/${caseId}/status`,
      { check_status: status },
      { headers: this.headers }
    );
    return data.data;
  }

  async getStats() {
    const { data } = await axios.get(`${this.baseUrl}/cases/stats`, { headers: this.headers });
    return data.data;
  }
}

Python — Vendor Client Integration

python
import requests
from typing import List

class KNKClient:
    BASE_URL = "https://api.example.com/api/v1"

    def __init__(self, api_key: str):
        self.session = requests.Session()
        self.session.headers.update({
            "x-api-key": api_key,
            "Content-Type": "application/json"
        })

    def get_status(self, application_id: str) -> dict:
        r = self.session.get(f"{self.BASE_URL}/client/status/{application_id}")
        r.raise_for_status()
        return r.json()

    def get_bulk_status(self, application_ids: List[str]) -> dict:
        r = self.session.post(
            f"{self.BASE_URL}/client/status/bulk",
            json={"applicationIds": application_ids}
        )
        r.raise_for_status()
        return r.json()

    def get_all_cases(self) -> dict:
        r = self.session.get(f"{self.BASE_URL}/client/status/vendor")
        r.raise_for_status()
        return r.json()

# Usage
client = KNKClient(api_key="knk_live_xxxxxxxxxxxxxxxxxxxx")

# Single case
result = client.get_status("REF-2026-001234")
print(f"Status: {result['status']}, Remark: {result['remark']}")

# Bulk check
bulk = client.get_bulk_status(["REF-2026-001234", "REF-2026-001235"])
for case in bulk["cases"]:
    print(f"{case['applicationId']}: {case['status']}")

# All vendor cases
all_cases = client.get_all_cases()
print(f"Total vendor cases: {all_cases['count']}")
